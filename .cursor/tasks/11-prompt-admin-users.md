# Configuration → Users (admin, Eloquent auth + CRUD)

## Цель

Подраздел **Users** в группе **Configuration**: **полноценный CRUD** пользователей админки, auth перевести на **Eloquent**-модель, поля пароля с **иконкой «показать пароль»**, флаг **`is_active`**.

## Ориентиры в проекте (изучить до кода)

- Текущая схема admin auth: `config/auth.php` (guard `admin`), User/provider, существующие login/register views и контроллеры.
- Паттерн форм: `ADMIN_PANEL_PATTERN.md`, соседние модули с password fields (если есть).
- Правила проекта: Form Request для create/update, хеширование паролей через стандартные средства Laravel.

## Задачи по пунктам

1. **Auth на Eloquent:** провайдер `admin` должен использовать Eloquent User-модель (ту же, что и для CRUD, или согласованную с проектом); убрать/заменить устаревшие custom user providers, если есть — без ломания сессий и guard.
2. **CRUD:** index (таблица/список), create, edit, delete (и политика удаления — нельзя удалить себя / последнего super-admin — **если** так заложено в проекте; иначе минимальные разумные ограничения + тесты).
3. **UI:** для полей **new password** и **confirm password** (create/edit) — кнопка-иконка **показать/скрыть пароль** в том же визуальном стиле, что и остальные admin-формы (Bootstrap, существующие иконки/классы).
4. **Модель:** поле **`is_active`**: миграция, fillable, отображение в формах; **не** пускать в админку неактивного пользователя при логине (middleware или явная проверка после аутентификации — согласно паттерну проекта).

## Тесты и проверка (обязательно)

- Feature-тесты: логин с активной/неактивной учётной записью, CRUD пользователей (с правами — под тем admin, который в проекте положен), валидация пароля, обновление без смены пароля (если supported).
- Запустить тесты auth + нового модуля; ничего не ломать в существующих тестах.

## Ограничения

- Без согласования не менять: публичный guard `web`, схему сессий не из этой задачи, архитектуру пространств имён.

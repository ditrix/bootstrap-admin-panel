# Configuration → Redirections (301 CRUD)

## Цель

Добавить подраздел **Redirections** в группе **Configuration**: табличный **CRUD** для хранения **301** редиректов (откуда / куда, активность).

## Ориентиры в проекте (изучить до кода)

- Любой существующий **табличный** admin CRUD (список + create/edit) в `resources/views/admin/pages/`, соответствующий контроллер и маршруты в `routes/web.php`.
- Валидация через Form Request; стилистика списка/таблицы — как в проекте (Blade, при необходимости DataTables — по паттерну соседних модулей).
- Сайдбар и `AdminLayoutComposer` — как для других пунктов admin.
- `.cursor/skills/ADMIN_PANEL_PATTERN.md`, `SKILLS.md`.

## Модель (имя согласовать, например `Redirect` / `SeoRedirect`)

```php
protected $fillable = [
    'slug_from',
    'slug_to',
    'is_active',
];
```

## Требования к поведению

- Индекс с пагинацией/поиском — **если** так принято в аналогичных CRUD в этом репозитории; иначе — минимальный рабочий список в стиле проекта.
- Уникальность и формат `slug_from` (и при необходимости `slug_to`) — зафиксировать в правилах валидации; избегать дублей исходных путей.
- **Применение 301** на уровне приложения: либо middleware/сервис, который по входящему пути ищет активную запись и отвечает `redirect()->to($slug_to, 301)`, либо явно описанный в коде механизм; не смешивать стили — следовать тому, как уже сделаны редиректы в проекте (поиск по коду: `301`, `redirect`).

## Тесты и проверка (обязательно)

- Feature-тесты: CRUD (или эквивалент по маршрутам), валидация, уникальность, переключение `is_active`.
- Если реализован runtime-редирект — тесты на совпадение пути, неактивную запись, отсутствие записи.
- Запустить тесты модуля и убедиться в зелёном прогоне.

## Ограничения

- Не добавлять лишние сущности и не рефакторить смежные модули без запроса.
